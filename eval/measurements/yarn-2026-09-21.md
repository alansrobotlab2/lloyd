# YaRN ×2 on the primary: what it costs, measured (2026-09-21)

Question: `architecture/vllm.md` §4 kept the YaRN shadow checkpoint switched
off because its short-prompt cost was "unmeasured on this box". This measures
it, and everything else an enable would need to know, on the production build
(vLLM main `dff1bde`, FP8 KV, 14.0 GiB, MTP k=3, chunk 4096).

Design: **production (B1) → YaRN → production (B2) → YaRN → production**, all under `round restart --only
agent-llm-primary` with the worker pool paused and idle. The YaRN arm was the
one-shot arm env (`MODEL_DIR=…-yarn2 MAX_MODEL_LEN=524288`), so no tracked
file changed and every later boot was production. Every request ran at
priority 5 and only while the engine reported nothing running or waiting.
The harness is `yarn-2026-09-21/yarn_ab.py` and `needle.py`. Retrieval, the
250k bucket, the stall check and the extra tool-choice runs ran on B2's boot.

## The noise floor is the finding that makes the rest readable

- **Production reproduces itself bit-for-bit on short prompts, across a
  reboot.** B1 and B2 agreed on all 229,950 scored tokens exactly, and a same-
  boot rerun did too. So on short prompts every difference in the YaRN arm is
  YaRN's.
- **But the request's *shape* is a large source of variation.** The same
  context scored inside a 480-token window instead of a 512-token one flips the
  top-1 token at 19% of positions (per-token σ 0.94 nats, 15.7% of tokens move
  over 1 nat) while mean NLL moves +0.006 [+0.001, +0.011]. Per-token agreement
  is therefore a poor gauge on this engine; mean NLL is the metric.
- **Long contexts vary boot to boot even on production.** At 20k and 150k, B1
  and B2 agreed on only ~88% of top-1 tokens (prefix-cache state changes how a
  long prompt is chunked). That is the floor for the long-context rows below.

### Tool choice is the one signal that leans against YaRN

Across the web set (`eval/tool_choice_queries.yaml`, 20) and the code-nav set
(`eval/code_nav_queries.yaml`, 15), three runs each, six queries scored
differently: YaRN worse on five, better on one — a query-level sign test of
p ≈ 0.22, not conclusive. One flip is persistent under an identical prompt
(same prefetch skills injected in all six runs): *"Is `_prune_reasoning` used
anywhere, or is it dead code I can delete?"* went to `graph_explain` 3/3 on
production and to `Bash`/`Grep` 3/3 on YaRN. Because the engine is
deterministic, three runs of one prompt are closer to one observation than
three, so 35 queries cannot separate a real ~5-point loss from chance.
Static YaRN applies to every request, so this is a worker-round question, not a
long-thread one: settling it needs a few hundred distinct decisions (real user
turns replayed to their first tool call on both arms, disagreements graded).

## What this does not cover

- Tool choice beyond the 35 queries above (the open question).
- Any task with a correctness grade other than exact-match retrieval and the
  tool-choice sets; the autoresearch bench is 13 tasks graded by the primary
  itself, so an arm would be grading its own answers.
- `models.primary.context_length`: nothing here raised it. Compaction keys off
  it (`app/compaction.py::truncation_threshold`), so an enable that raises it
  moves every session's truncation from ~210k to ~472k and microcompact's
  trigger from ~151k to ~340k; that is a separate design decision.

## Preserve-thinking A/B (#617), folded into the B2 boot

`eval/run_preserve_thinking_eval.py --trials 3`, production config, pool
paused. Medians over trials:

| vs `off` | `window=6` (shipped) | `all` |
|---|---|---|
| wall seconds | −15.7% | −28.9% |
| output tokens | −34.4% | −34.3% |
| tool calls | −11.4% | −18.2% |
| turn-2 peak input | −3.2% | +1.6% |
| answer chars | −2.8% | −1.8% |

All nine sessions completed. Carried reasoning cuts a third of the output
tokens and 11–18% of tool calls with the same answers. `window=6` vs `all`
differ by less than the trial spread (window 111–129 s, all 86–122 s); the
window keeps turn-2 peak input ~5% lower. No change to the shipped default.

## Reproducing

    YARN_AB_OUT=/tmp/yarn_ab python yarn_ab.py corpus
    python yarn_ab.py dense ARM; python yarn_ab.py sparse ARM; python yarn_ab.py decode ARM
    python needle.py build; python needle.py run ARM 16000,64000,128000,200000,250000 8
    python needle.py hard ARM 16000,64000,128000,200000,250000 4
    python yarn_ab.py compare B1 Y B2; python needle.py report hard P Y

Run from `yarn-2026-09-21/` with the lloyd venv, the pool paused and nothing else
on :8096. Prompt logprobs are kept to ≤512-token windows on purpose: a
4096-token chunk of full-vocabulary logprobs (248,320) is ~6 GB transient on a
card with ~3 GB free, and an engine that dies autorestarts without the host-RAM
gate. Long contexts are read one next-token request per position instead,
which reuses the prefix cache and computes logits for one token.
